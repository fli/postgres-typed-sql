# Cold predicate analysis performance

The analyzer now reuses completed query scopes and expression fingerprints within one compiled statement. It avoids rebuilding the same predicate facts for repeated result-column, row-bound, subquery, CTE and index analyses. Public analysis, generated TypeScript, codecs, provenance and publication behavior stay unchanged.

## Local result

A 1,216-statement consumer corpus ran through its unchanged generation wrapper in six pairs. The order reverses in successive pairs. Each run starts a fresh Node process and generates all outputs from an empty output inventory. The wrapper performs its normal input capture, preflight, generation, validation and publication. Verification and removal of previous outputs happen outside the measured region.

| Measurement              |      Baseline |     Candidate |
| ------------------------ | ------------: | ------------: |
| Median wall time         |       32.76 s |       17.25 s |
| Wall-time range          | 32.10–35.36 s | 16.80–18.88 s |
| Median user + system CPU |       37.62 s |       21.97 s |
| Median process peak RSS  |       2.30 GB |       2.38 GB |
| Largest observed RSS     |       2.36 GB |       2.40 GB |
| Successful runs          |           6/6 |           6/6 |

The measured wall-time reduction is 47.36%, or 15.51 seconds per complete local generation. Process CPU decreased by 41.59%. GB uses decimal bytes. Measurements use macOS ARM64, Node 26.10.0 and ten logical CPUs. No profiler or code instrumentation runs in the headline comparison.

Every run generated 1,216 statement modules and one catalog file. All generated bytes, complete public analysis and configuration provenance matched exactly. All authored input hashes remained unchanged. The preserved baseline is commit `996a934` before these changes, with the same package and native-engine versions as the candidate.

The fixture copies every SQL input, schema and configuration file. It omits unrelated repository files, so discovery traversal differs from a complete consumer checkout. Upstream query generation and downstream formatting are excluded. These are local generation results, not measured hosted CI or full-pipeline savings. A smaller initial candidate had overlapping ranges under substantial load drift; that result does not establish a separate benefit for expression caching or the scan change.

## Work removed

Separate instrumented verification runs compared the full internal IR for all 1,216 statements byte for byte. The following counts are diagnostic operations, not timings.

| Operation                             |   Baseline | Candidate |
| ------------------------------------- | ---------: | --------: |
| Scope requests                        |    354,078 |   354,078 |
| Completed-scope cache hits            |          0 |   323,556 |
| Predicate normalization calls         |  7,936,618 |   563,837 |
| Input keys presented to normalization | 47,342,726 | 3,258,417 |
| Expression-key function calls         | 23,865,125 | 1,440,063 |
| Uncached expression-key computations  | 23,865,125 |   666,360 |

Baseline key computations include early null or unsupported returns. The candidate's serializer runs only after a non-null expression cache miss. Scope reuse eliminates most repeated fact construction; the expression cache also avoids repeated serialization within the remaining analysis. Neither cache changes truth evaluation.

## Correctness boundaries

A statement owns one work context and one catalog. Completed scopes are keyed by exact query object and exact parent scope object, with a distinct null-parent slot. CASE parents and aggregate scopes remain distinct. Synthetic queries retain their own identities. Only completed successful construction is cached. Existing cycle guards, failures, WHERE and join order, empty-group behavior and HAVING processing remain intact.

Expression fingerprints are keyed by query, input/result phase and expression object. The existing serializer remains the equality definition. It retains type, collation, nulling relations, DML row image, filter and aggregate eligibility distinctions. Unsupported results remain null, and exceptions are not cached. Query, expression, catalog, scope and installed fact contents must remain immutable during synchronous statement normalization. Weak maps and per-statement ownership prevent reuse across independent statements or catalogs.

Fact maps and ordered string sets retain their existing representation. The final per-variable normalization step gathers literal and excluded keys in one traversal, then parses them in the existing order. Merge boundaries and insertion order do not change. Normalization is history-sensitive, especially repeated exclusion expansion, so duplicate-key merges cannot simply be skipped.

Verification includes 12,000 seeded fact operations with ordered results, readers and retained-branch checks; malformed-key and overlapping-prefix cases; 4,800 expression comparisons and 48 complete-scope comparisons across contexts; and a 38-statement adversarial IR and generation comparison. Twenty-six SELECTs execute against real rows. The failure comparison checks diagnostics and the complete input/output inventory, including an existing stale output. A runtime regression test checks CASE parents, CTE reuse, window rows and empty aggregate groups. The complete package suite, packed consumers and external wrapper/native-consumer contracts are recorded in the local validation report.

## Reproduce

Build and preserve the baseline package, including its `package.json` and complete `dist` directory. Build the candidate normally. Supply separate writable artifact directories for each comparison.

```sh
node scripts/compare-predicate-facts.mjs BASELINE/dist/analyzer-predicate-facts.js CANDIDATE/dist/analyzer-predicate-facts.js
node scripts/compare-expression-keys.mjs BASELINE/dist/analyzer-ir.js CANDIDATE/dist/analyzer-ir.js
node scripts/compare-generation.mjs BASELINE CANDIDATE ARTIFACT_DIRECTORY
node scripts/benchmark-generation.mjs READ_ONLY_CONSUMER_CHECKOUT BASELINE CANDIDATE ARTIFACT_DIRECTORY 6
```

The large benchmark expects a wrapper corpus with `apps`, `packages`, `packages/db/schema.sql`, `packages/db/postgres-typed-sql.config.mjs`, and `packages/db/scripts/generate-typed-sql.mjs`. It copies authored inputs into a private fixture and links each supplied producer in turn. It records build identities, inputs, outputs, status, resources and individual timings. Six pairs counterbalance which side runs first. Keep other expensive work out of the measurement window.

The expression comparison temporarily creates uniquely named probe modules beside the supplied built analyzers and removes them in `finally`. It does not add public exports or modify the original modules. The generation comparison uses a self-contained synthetic corpus and checks internal IR as well as public artifacts.

## Adoption

This patch requires no consumer API changes. Release it under a new package version after review, then update the consumer dependency and lockfile. If the consumer wrapper asserts the exact producer version, update that assertion together with the dependency while retaining provenance validation. The local experiment intentionally keeps both producer versions equal for exact differential comparison. No publication, dependency update, hosted CI, push or merge is part of this measurement.
